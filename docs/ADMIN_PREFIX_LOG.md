# Admin URL-prefix removal implementation log

This is the best-effort P0–P6 implementation of `ADMIN_PREFIX_REMOVAL_PLAN.md`, applied after the standalone app source was created. The split plan's structure is implemented, but A0–A7 could not be declared green because this environment lacks the complete locked dependency installation and live Cloudflare/backend environment. Accordingly, the prefix-removal implementation is not a production acceptance sign-off.

## P0 — Preconditions and baseline

- Confirmed the original ZIP did not contain `admin/`; the standalone admin was created in this same task.
- Full `admin` baseline was unavailable because the original repository did not include it and npm dependency installation timed out / lacked cached package metadata.
- Route snapshots are script-generated by `admin/scripts/dump-routes.mjs`; outputs: `docs/admin-prefix/nav-before.json`, `routes-before.json`, `nav-after.json`, `routes-after.json`.

## P1 — Classification

- Added TypeScript compiler API classifier in `admin/scripts/lib/classify.mjs` and runner `admin/scripts/classify-admin-prefix.mjs`.
- Reconstructed and scanned the original pre-prefix admin source from the supplied ZIP: 558 matching literals in 191 TS/TSX files; 271 API and 287 PAGE. This original classification and its manual/nonliteral notes are in `docs/admin-prefix/CLASSIFICATION-P1.md`.
- Final standalone admin scan: 276 matching literals; 271 API, 0 PAGE, 5 ambiguous/compatibility literals. Six non-literal URL/pathname forms are flagged for review. The remaining ambiguous items are intentionally retained legacy-route test/normalizer fixtures.
- PAGE classification did not modify API paths. No API route changes are intended.

## P2 — App routes

- Dashboard is `/`; the nav matcher special-cases `/` to exact equality and uses equality or path-boundary prefix matching for other items.
- `AdminApp` mounts index route for `/`; page routes use root-relative paths; care visits nested route and detail routes were adjusted; the default authenticated fallback redirects to `/`.
- Updated the care-screen pathname regex and browser link/guard paths.
- Added the guard test `admin/src/routing/no-admin-prefix.test.mjs` and nav tests for `/`, `/care`, `/care/clients/123`, `/mail`, and `/careers` vs `/care`.
- Classifier acceptance result: 0 PAGE literals in admin source. `drop-admin-prefix.mjs --dry-run` reports 0 changes and leaves the 271 API literals untouched.

## P3 — PWA, service worker, native

- Manifest start URL is `/mail`, scope is `/`; `admin/src/pwa/manifest.test.ts` covers these values and the standard/maskable icons.
- Service worker normalizes old `/admin/...` push payload URLs, keeps the `nest-mail-push` message and visible/focused quiet behavior, and opens the root-path notification target.
- `/api/`, `/assets/`, `/sw.js`, and `/manifest.webmanifest` are excluded from navigation fallback.
- Capacitor config points at `dist`; Android id remains `ug.nesthomecare.admin`. Capacitor config was source-reviewed; no Android SDK was available to build/run the native app.

## P4 — Backward-compatible redirects

- Added client route `admin/*` using `normalizeAdminUrl`, preserving query/hash and leaving `/administrator` and other origins unchanged.
- Added root redirect rules to `admin/public/_redirects`, and public-site redirects in both `frontend/` and `frontend-thread/` configs.
- Worker routing config has `run_worker_first: ["/api/*"]`; Worker code proxies only `/api` and `/api/*`, while non-API paths go to static assets. SPA fallback serves the app shell for deep routes. Cloudflare deployment behavior was not live-tested.

## P5 — Backend links

- Backend link builders now use `ADMIN_URL` and root page paths for set-password, agreements, SOS, alerts and mail push.
- Backend API router prefixes remain `/admin/...` under `/api/v1`; these were deliberately not changed.
- Production deployment must explicitly set `ADMIN_URL=https://admin.bhcug.com` before enabling root-path links. The config fallback to `FRONTEND_URL` is preserved from the split plan but must not be relied upon after the URL cutover.
- Added `backend/tests/test_admin_url_links.py`; test execution blocked because `beanie` is not installed. `ruff` is unavailable.

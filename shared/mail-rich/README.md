# Shared Nest Mail rich-content foundation

This folder is the only authoring location for mail-rich code. The committed app copies are generated by `node scripts/sync-mail-rich.mjs` into `frontend/src/shared/mail-rich/` and `nurse/src/shared/mail-rich/`. Do not edit those generated copies.

The backend policy copy is `backend/app/modules/mail/html_policy.json`; its equality with `policy/mail-html-policy.json` is checked by `backend/tests/test_mail_html_policy.py`.

The shared viewer builds a safe DOM tree from the allow-list. It does not use `innerHTML`, `dangerouslySetInnerHTML`, iframes or Shadow DOM. Inline style rules are filtered and applied through CSSOM. CSS classes use only these variables, with fallbacks:

- `--mr-bg`, `--mr-fg`, `--mr-muted`, `--mr-line`, `--mr-accent`, `--mr-warn-bg`, `--mr-error`, `--mr-radius`, `--mr-gap`.

Each app maps these variables to its existing theme tokens. The viewer's message paper remains light (`#fff` / `#1a1a1a`) so email colours stay legible in dark themes.

`MailUiKitProvider` is the adapter boundary. Admin and nurse apps supply their own `Button`, `ToolbarButton`, `Select`, `TextField`, `Dialog`, and `Notice` primitives plus a complete `MailLabels` object. Shared code does not use app translation functions.

The browser upload hook uses presigned PUT URLs; deploy CSP and bucket CORS must permit the configured object-storage origin. `nurse/vite.config.ts` and `nurse/public/_headers` still need the storage host in `connect-src` (and `img-src data:` for inline previews). No remote mail image is loaded by the shared viewer; the application must confirm before explicitly loading a remote image.

The TipTap editor (`react/MailRichEditor.tsx`, lazy-loaded) is now included, pinned at 3.31.4. Measured on the nurse build: 320 KB gzip total, 151 KB for the editor chunk. The owner raised the budgets to 360 KB total / 160 KB per route chunk. See `docs/PINS_MAIL_RICH.md`.
